**Part CA (part_ca_refunds_disputes_payouts.sql)** – run after BZ, then deploy the web build and the edge functions `process-refund` (and redeploy `billing-webhook`). The money side of the admin console: Payments → Refunds, Disputes and Payouts. **Part CG (part_cg_auto_detection.sql)** – run after CF, then deploy the web build. Automatic detection. (1) Screening rules (Admin → Detection & Workload; eight starter rules for scam links, requests for an OTP, "pay a fee to be cast", guaranteed returns, betting spam, Telegram lures from new accounts, explicit solicitation and impersonating the team) are checked on every new or edited post, comment, listing and job. A match opens a case in the normal queue marked "found automatically", at the rule's priority, and hides a post or comment until a person looks if the rule says so. Nothing is removed automatically. New listings are also checked for a new account pricing far below similar listings and for copied text. (2) Throttles: posts and comments an hour, listings and jobs a day, stricter for accounts under 1 and under 7 days old (all editable); staff and system jobs are not limited. There is no image scanning (removed: not needed now); images are reviewed only when someone reports them, and a child-safety report uses the fast lane. If an earlier run of this part created the image queue, this run removes it. Cases with no reporter need a build that handles a missing reporter (this web build does; the mobile apps do not show cases).

**Part CH (part_ch_workload_and_second_review.sql)** – run after CG, then deploy the web build. Second review: a share of closed cases (default 10%, every child-safety case) is handed to a different staff member under Moderation → Second review, who says whether they agree; a disagreement alerts the admins and shows in Detection & Workload.
